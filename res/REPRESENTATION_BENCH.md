# IR–VI 结构表示横向基准（Representation Benchmark）

在 **HDO `aligned`** 上做，用**已知合成变换**生成精确 GT，因此不需要数据集提供 flow。

```powershell
python -B -m res.representation_bench --pairs 4 --scale 8
python -B -m res.representation_bench --pairs 4 --scale 16
```

数据：HDO `aligned` 的 4 对（跨 4 个不同序列），640×480。该基座经实测已对齐
（同模态平移搜索最优位移 = 0，跨模态 NCC 0.43，而错配伙伴仅 0.21）。

---

## 一、协议

| 项 | 设置 |
|---|---|
| moving | 粗尺度 IR，施加已知仿射/弹性采样映射 W |
| fixed | 粗尺度 VIS |
| 精确 GT | `F(p) = W⁻¹(p) − p`（推导得到，非近似） |
| 变换施加位置 | **在匹配尺度上**，不是全分辨率 |
| 匹配 | 逐像素 all-pairs 余弦 + 互匹配 |
| EPE 单位 | 全分辨率像素 |

**"变换施加在匹配尺度"这一点是修出来的，不是随便选的。** `area` 池化只对步长整数倍的
位移保持平移协变性：在全分辨率上 warp 再池化，会让 5 格位移完美匹配、2.5 格位移被
池化网格彻底破坏——量到的是重采样器，不是表示。第一版基准没注意这点，得到了
"d=40/80 完美而 d=20 崩溃"这种非单调的荒谬结果。改到粗尺度施加变换后结果才自洽。

---

### 2.3 逐像素指标：全部接近随机

| 指标 | 1/8 (N=4800) | 1/16 (N=1200) | 随机基线 |
|---|---|---|---|
| top1_acc 最好 | lss 0.045 | mind_fixed 0.053 | 0.0019 / 0.0075 |
| margin 最好 | grad_patch 0.011 | monogenic 0.017 | — |
| 熵 最低（最尖锐） | monogenic 0.63 | monogenic 0.56 | 1.0 = 均匀 |

`top1_acc` 是随机基线的 7–24 倍，**高于随机但完全不可用**：正确对应在位次上仍然
劣于绝大多数候选。`margin` 全部 ≤ 0.017，印证了此前在 VTMOT 上量到的
`top1 − top2 ≈ 0.0005` 量级。

### 2.4 全 token 的 margin 加权拟合：普遍失败

`epe_affine`（用全部 token、权重 = margin）在两种尺度上都落在 **165–245 px**，
12 个表示无一例外。因为逐像素对应是随机的，加权拟合被噪声主导。
**这说明"直接用 Softmax 权重做加权最小二乘"这条路在特征未训练时是坏的。**

## 三、结论

### 3.1 全局一致性有效，逐像素对应无效

这是本次基准最重要的结果，且两者同时成立：

- **大位移能被可靠恢复**：MIND 的一致性投票在 **40 px 和 80 px 位移上误差为 0.0 px**，
  20 px 为 5.2 px。你方案"Global Matching 负责大位移"的前提**成立**。
- **但逐像素对应接近随机**：同一个 MIND、同一批数据，`top1_acc` 只有 0.017。

原因是聚合方式而非表示本身：单个 8×8 块的描述子有歧义，但**所有像素的错误答案分散在
几千个候选上，而正确答案获得一致加成**，于是众数仍然精确。
这正好是 Hough / 互匹配投票的机制。

**设计含义：粗配准阶段必须做全局聚合（投票/参数拟合），不能依赖逐像素 soft-argmax 期望。**
这也解释了为什么你项目里已有的做法——上千个匹配点约化成 6 个自由度——是有效的，
而我方案评估中批评过的"dense soft-argmax 直接当粗流"是错的。

### 3.2 MIND 是全局一致性最好的表示，且优势明显

| 排名 | 表示 | vote_err 均值(1/8) | 大位移表现 |
|---|---|---|---|
| 1 | **mind** | **10.1** | 40/80 px → 0.0 px |
| 2 | lss | 24.5 | 40/80 px → 2.0 px |
| 3 | grad_patch | 94.4 | 40/80 px → 97/141 px |
| 4– | orient / raw_patch / monogenic / pc_patch / census | 91–315 | 基本失败 |

`mind` 与 `mind_nol2` 结果**逐位完全相同**——因为 `MINDDescriptor.forward` 内部已经做了
L2 归一化，外部再归一化是幂等的。我此前建议的"不要做 L2 归一化"因此是**无效建议**，
归一化发生在模块内部。

`mind_fixed`（我提出的"局部方差归一化 + 平坦区门控"改法）是**平局，不是改进**：
1/8 上票误差 12.0 vs 原版 10.1（更差），1/16 上 11.7 vs 19.9（更好）。

### 3.3 我此前推荐的 Phase Congruency / Monogenic **没有得到支持**

必须明确纠正上一轮的判断。我当时基于"不变性 + 空间锐度"推荐 PC/单演信号。实测：

- monogenic 的 softmax 熵最低（**0.63 / 0.56，全场最尖锐**），
- 但它的投票误差是**全场最差之一**（157 / 159 px）。

**它给出的是"自信但错误"的匹配。** 锐利度和正确性在这里是负相关的——
高熵的 MIND（0.95，最弥散）反而是唯一能形成正确一致性的表示。

这是一个一般性的教训：**用 softmax 熵或峰值来衡量匹配质量会误导**，
必须用**与 GT 对比的一致性精度**（本基准的 `vote_err`）来选表示。

### 3.4 旋转还需要专门处理

`rot5` 投票误差 17–25 px，`rot10` 达 39 px 且内点常常不足。
纯平移投票无法表达旋转（10° 在 640 px 宽上跨幅 ±56 px，众数只能抓住中心附近）。
**需要把投票推广到仿射/相似变换空间，或者粗到细逐级投票。**

### 3.5 对方案的具体修订

| 方案原设计 | 实测结论 | 建议 |
|---|---|---|
| MIND → 1/8 all-pairs → softmax → soft-argmax 期望得粗流 | 期望值会塌到中心；逐像素对应接近随机 | 改为 **Hough/一致性投票 → 内点集 → 闭式拟合** |
| Global Matching 找大位移 | ✅ 成立（MIND 40/80 px → 0 px） | 保留，但聚合方式换成投票 |
| 手工特征即可 | ❌ `top1_acc` 0.017，`margin` ≤0.011 | 学习投影头是**必需**的，不是优化 |
| confidence = max(P) 指导 DCN | 熵与正确性负相关 | 用**一致性内点比例**做 confidence，不要用 softmax 峰值 |
| PC / 单演信号做主打表示 | ❌ 投票误差最差 | 用 **MIND**；PC 仅作为可选通道 |
| Phase Congruency 替代实验 | 已有结果 | monogenic/pc_patch 均失败，可跳过 |

### 3.6 仍然无法用 HDO 回答的问题

本基准全程**不依赖 GT flow**（GT 由合成变换精确导出），所以能在 HDO 上跑。
但它回答不了方案第十节的监督损失和第十三节的 EPE / PCK / 位移分桶——
HDO 没有 GT flow，而合成 GT 只对合成分布成立。
